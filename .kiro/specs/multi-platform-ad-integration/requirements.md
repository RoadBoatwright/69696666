# Requirements Document

## Introduction

本系统是一套「AI 驱动型外贸精准获客投流平台」（平台代运营式多平台投流获客系统），对标竞品 WÀ商机，核心价值是让外贸商家以极低投入获得持续的海外买家询盘：商家只需提供**已制作完成的成品广告素材（广告视频/图片等）**，由系统 AI 自动完成多平台广告计划创建、优化与投放，商家每日接收回流的商机并跟进即可，无需自行登录各平台后台、也无需掌握投放技能。

**关于素材与 AI 的边界（重要定位）**：本系统的产品素材为商家**已制作完成、可直接投放的成品广告创意**；系统对其只做**平台合规校验（格式、尺寸、时长、文件大小等）与多平台挂载/引用**，不负责广告创意的设计与制作。AI 的职责限定在**投放侧**——按买家画像生成广告计划草案、以「商机成效最大化」优化投放、对回流商机做 Gemini 背调与 L1-L4 分级；AI **不参与广告创意的从零设计制作**。各平台官方提供的 AI 创意生成能力（需求 31）作为**可选增强项**接入，默认获客主线以成品素材直投为准。

系统区分三类角色，建广告与投放由 AI 自动完成，资深投手仅在投放后按需介入优化：

- **外贸商家客户（Merchant）**：只负责提供成品广告素材并接收、跟进回流的商机；不自助操盘广告、不负责创意设计制作。
- **平台投手（Operator）**：资深运营人员，在 AI 自动建广告与投放之后，按需介入做进一步优化与人工校准，并管理回流商机；非每次投放的必经环节。
- **系统管理员（Administrator）**：管理各平台凭据、账户池与角色权限的人员。

系统遵循竞品验证过的「五步获客法」，其中前三步由系统 AI 自动完成：① 商家提供成品广告素材（已制作完成、可直接投放的广告视频/图片，系统只做平台合规校验与挂载，不做创意设计）；② 系统 AI 自动按买家画像（国家/地区 + 行业 + 职位）创建广告计划；③ 系统 AI 以「商机成效最大化」为目标自动优化并投放；④ 买家填写高门槛留资表单（公司名 + 姓名 + 电话 + 邮箱，用以筛掉无效流量）；⑤ 商机当日回流后经 Google Gemini 背调，按买家意向等级（L3/L4 高意向优先）进入跟进开发。系统以此支撑「当日投放当日获客、单条有效询盘成本可控、客户资产永久归属企业、商家传完资料后每日接询盘即可」的获客承诺。

本系统的前三步（建广告计划、AI 优化、投放）由系统 AI **自动完成**，无需每次人工确认；AI 的职责均在投放侧——自动生成广告计划、自动优化投放、对回流商机做背调与分级，不含广告创意的从零设计制作。资深平台投手仅在投放后的**后续优化阶段按需介入**做人工校准，回流商机由商家负责跟进开发。这是一套「AI 自动化为主、资深投手后续优化为辅、商家收单跟进」的协作模式，而非每次投放都需人工逐次审批的半自动流程。系统可选地提供「人工审核模式」开关，开启后投放前需投手确认，默认关闭以保持前三步全自动。

本期接入三个主力广告平台：Meta（Facebook/Instagram/WhatsApp）、Google Ads（含 YouTube），并在二者之上**差异化接入 TikTok**——这是本系统相对竞品的核心差异。系统采用各平台官方的「代客户管理」授权模式（Meta System User + on-behalf-of、Google MCC、TikTok Business Center Agency + OAuth），通过统一的「账户授权中心」集中管理各平台凭据与令牌生命周期，并通过「统一广告对象模型」对投手屏蔽平台差异。

本文档全部需求（共 35 条）均为**本期实现范围**，分两组组织：**第一组（需求 1-21）为获客主线**，对标竞品五步获客法；**第二组（需求 22-34）为高级投放能力全集**，充分利用 Meta、Google、TikTok 三平台官方 API 的高级与独有能力（Advantage+、Performance Max、Spark Ads、智能出价全集、A/B 实验、投前预估、消息广告、AI 创意、商品目录、离线转化、广告版位等），用以彻底榨干官方 API 能力、全面超越竞品；**需求 35 为商机数据对外 API**，为后续自有 CRM 系统接入预留标准化的客户数据拉取与增量同步接口。两组及需求 35 均本期交付，仅 LinkedIn（需求 34）作为第二期平台扩展位预留。

**核心打磨重点（极致投流引擎）**：本产品的核心竞争力集中在投流引擎的三步主线——① 精准建广告计划（按国家/地区 + 行业 + 职位锁定买家画像）、② AI 以「商机成效最大化」优化并多平台自动投放、③ 高门槛留资筛选——这三步必须做到**效果极好、回流客户质量极高、购买意向极高**。为此系统贯彻「以有效高意向商机为唯一优化目标」的原则：投放优化目标对齐有效高意向商机数（而非曝光或点击量）；受众定向以高意向种子做相似扩展并以负向/排除定向滤除低意向人群；高门槛留资表单在公司名 + 姓名 + 电话 + 邮箱必填基础上叠加**反作弊、企业身份校验与重复/机器人过滤**，确保仅高质量、强购买意向的线索回流为商机。背调、分级、跟进、看板等后续环节保留并服务于该目标，但产品打磨力度优先投入前三步。

系统贯彻以下既有原则：所有平台凭据均为敏感信息，必须加密存储且不得明文记录到日志（脱敏）；缺少 API 凭据时对应能力**优雅降级**，标记为不可用而非崩溃；调用失败时**保留已生成内容或原始数据以待重试**；**单份素材或单个维度失败不影响其余素材与维度**（单点失败隔离）；各商家**数据相互隔离**，仅能访问自身资产；指标计算遇零除时**标记为「不可计算」**而非报错。

本文档定义系统的功能性需求，采用 EARS 模式表达，遵循 INCOSE 质量规则，作为后续设计与实现的依据。

### 系统输入与产出概览

**系统输入（商家侧尽量少）**：① 成品广告素材（已制作完成的广告视频/图片，直接投，AI 不做创意制作）；② 产品定位描述（卖什么、卖给哪些国家/行业/职位，可简至一句话，AI 据此自动推导买家画像）；③ 广告预算；④（一次性、管理员侧）Meta/Google/TikTok/Gemini 平台凭据。

**系统处理（默认全自动，可切专家把关档）**：AI 自动推导买家画像 → 自动建多平台广告计划 → 以「有效高意向商机数」为目标自动优化与投放 → 高门槛留资 + 质量闸门筛选 → Gemini 自动背调补全 → 自动 L1-L4 意向分级。默认无人工逐步干预；人工审核模式可按全局或单个商家切换为「投放前投手确认/微调」。

**系统产出（核心交付物）**：一份份**精准高意向客户档案**，以三种形态交付——商机清单（按等级/平台/跟进状态筛选，L4 优先）、单客户详情页、可一键导出的 Excel/CSV。每条档案 = 买家社媒主动留资（公司名 + 姓名 + 电话 + 邮箱及其余表单字段）+ 质量校验标注 + Gemini 背调补全（公司官网、地区、行业、职位、社媒、可信度评估）+ 买家意向等级。此外提供效果看板（含五项业务结果指标）与可导出的客户行业调查报告，并通过**商机数据对外 API**（需求 35）为后续自有 CRM 系统提供标准化的客户数据拉取与增量同步入口。

## Glossary

### 核心术语

- **广告系统（Ad_System）**：本平台代运营式多平台投流获客系统的整体后端，泛指无明确归属于某子模块的系统行为主体。
- **外贸商家客户（Merchant）**：只提供产品素材并接收、跟进回流商机的最终客户角色，不自助操盘广告。
- **平台投手（Operator）**：代多个商家创建广告计划、优化投放与管理商机的运营人员，是系统主要操作者。
- **系统管理员（Administrator）**：管理平台凭据、账户池与角色权限的角色。
- **账户授权中心（Auth_Center）**：集中管理各平台授权凭据与访问令牌的子模块，负责令牌的存储、刷新、过期预警、状态监控与撤销处理。
- **凭据管理器（Credential_Manager）**：负责密钥与凭据（app secret、developer token、System User token、OAuth token、Gemini API key 等）配置化存储、占位、后填、加密与脱敏的子模块，是账户授权中心的组成部分。
- **统一广告模型层（Unified_Model_Layer）**：将各平台「广告系列→广告组→广告」三级结构及其字段抽象为统一对象模型并屏蔽平台差异的子模块。
- **平台适配器（Platform_Adapter）**：针对单一广告平台（Meta、Google、TikTok）实现统一模型到平台原生 API 调用转换的子模块。
- **代客户管理（Agency_Management）**：通过平台官方授权机制代客户管理其广告账户的模式。
- **System User token**：Meta 平台用于代客户调用 API 的系统用户访问令牌。
- **MCC（Manager Account）**：Google Ads 经理账号，客户账号挂载在其下进行代管理。
- **OAuth token**：基于 OAuth 2.0 授权流程获得的访问令牌与刷新令牌。
- **广告系列（Campaign）**：广告三级结构的最高层，承载投放目标与整体设置。
- **广告组（AdGroup）**：广告三级结构的中间层，承载受众定向、预算、出价与排期设置。
- **广告（Ad）**：广告三级结构的最底层，承载素材与创意内容。
- **优雅降级（Graceful_Degradation）**：在缺失凭据或平台不可用时，系统将对应功能标记为不可用并保持其余功能正常运行，而非整体崩溃的行为。

### 获客与素材术语

- **AI 辅助建广告引擎（AI_Campaign_Assistant）**：以「商机成效最大化」为目标，依据**成品广告素材**与买家画像**自动生成**多平台广告计划草案（草案中素材为对成品素材的引用/挂载，不含创意设计制作）、默认自动投放，并基于回传指标对已投放计划自动优化（在授权范围内）或向资深投手提出优化建议的子模块，可借助平台官方 MCP 连接器；其推理能力依赖底层生成式 AI。
- **买家画像（Buyer_Persona）**：投放定向所依据的目标买家描述，核心维度为国家/地区、行业与职位，可附年龄、性别、兴趣等维度，用于生成广告定向与草案。
- **广告计划草案（Campaign_Draft）**：由 AI 辅助建广告引擎依据成品广告素材与买家画像**自动生成**的多平台（Meta、Google、TikTok）广告系列、广告组、广告、定向、预算、素材挂载与表单建议集合；其确认状态取值为「待确认」与「已确认」二者之一；当人工审核模式关闭（默认）时草案生成后**自动置为「已确认」并进入投放**，当人工审核模式开启时草案置为「待确认」、未确认前不得发布或投放。
- **人工审核模式（Manual_Review_Mode）**：系统的自动化档位开关，可由管理员全局配置、亦可按单个商家覆盖配置，默认关闭（全自动档）。**关闭（全自动档）**时 AI 生成的广告计划草案自动确认并投放，建计划/优化/投放/背调/分级全程无人工干预；**开启（专家把关档）**时广告计划草案在投放前需投手人工确认与微调后方可投放。同一商家任一时刻有且仅有一个生效档位。
- **产品定位描述（Product_Positioning）**：商家提供的关于所售产品、目标市场与目标客户的自然语言描述（可简至一句话），作为 AI 自动推导买家画像的输入。
- **买家画像来源（Persona_Source）**：买家画像的产生方式，取值为「AI 自动推导」与「人工指定」二者之一；AI 自动推导依据产品定位描述与成品素材生成画像草案，人工指定由投手直接给定画像维度。
- **底层生成式 AI（Generative_AI_Provider）**：为广告计划草案生成、投放优化与客户背景调查提供生成与推理能力的外部 AI 服务（如 Google Gemini），其凭据由凭据管理器按配置化、加密与脱敏范式管理。
- **MCP 连接器（MCP_Connector）**：平台官方提供的 Model Context Protocol 接入方式，用于 AI 优化能力。
- **产品素材（Product_Material）**：商家提供的**已制作完成、可直接投放的成品广告素材**，包括成品广告视频、成品广告图片、轮播图、以及配套的产品图片、PDF、规格书、报价单、说明书、认证文件等；系统对其只做平台合规校验与多平台挂载/引用，不做创意设计制作。
- **素材服务（Asset_Service）**：负责成品广告素材上传、平台合规校验（格式、尺寸、时长、文件大小等）、存储、管理与向各平台上传/引用的子模块；单份素材失败时隔离该素材并保留其余素材，不中断整批处理。

### 投放与数据术语

- **数据回传服务（Metrics_Service）**：负责从各平台拉取并归一化投放指标（曝光、点击、转化、花费、ROI 等）的子模块。
- **线索收集服务（Lead_Service）**：负责高门槛留资表单配置与线索回流采集的子模块。
- **高门槛留资表单（Lead_Form）**：在平台广告内嵌的留资表单，以公司名、姓名、电话、邮箱为必填高门槛字段，并叠加格式有效性校验、一次性邮箱/无效占位值识别、反作弊过滤与企业身份初判，用以筛掉无效流量与低意向人群、提高回流商机的质量与购买意向。
- **留资质量校验（Lead_Quality_Check）**：线索收集服务对每条回流留资执行的有效性与反作弊判定，包括邮箱/电话格式校验、一次性邮箱域名识别、无效占位值识别、机器人/批量提交识别与企业身份初判；命中低质量或疑似作弊的留资不计入有效线索。
- **Pixel/转化事件/Events API**：各平台用于追踪用户转化行为的追踪机制。
- **效果看板服务（Dashboard_Service）**：以统一口径聚合各平台投放效果与全链路业务结果、计算业务结果指标并生成可导出报告的展示子模块。

### 商机与背调术语

- **商机（Opportunity）**：在回流线索之上的增强概念，承载线索原始数据、背调结果、买家意向等级与跟进状态，是面向商家的可跟进开发对象。
- **Gemini 背调服务（Gemini_Verification_Service）**：调用 Google Gemini AI 对回流商机做客户背景调查、补全并校验可验证信息（公司、地区、行业、职位、网站、社媒等），并输出可信度评估与背调摘要的子模块；其凭据按配置化、加密与脱敏范式管理。
- **背调结果（Verification_Result）**：Gemini 背调服务对单条商机输出的结构化结果，包含校验后的客户信息字段、可信度评估与背调摘要；与原始留资冲突的字段同时保留两值并标注「待核实」。
- **可信度评估（Confidence_Assessment）**：背调结果中对客户信息真实性的量化或分级评估，用于商机意向分级与跟进决策。
- **商机分级引擎（Opportunity_Scoring_Engine）**：基于背调可信度评估、买家画像匹配度与行为数据计算买家意向等级的子模块。
- **买家意向等级（Intent_Level）**：对商机意向强弱的分级取值，取值集合为「L1」「L2」「L3」「L4」「未分级」五者之一且任一时刻唯一，其中 L4 表示最高意向、L1 表示最低意向、「未分级」表示分级所需数据缺失而无法计算。
- **跟进路由服务（FollowUp_Routing_Service）**：将商机路由进入企业 WhatsApp 与/或 CRM 跟进通道、记录跟进状态与触达时间，并生成销售跟进剧本的子模块。
- **企业 WhatsApp 通道（WhatsApp_Business_Channel）**：用于商机跟进开发的企业版 WhatsApp 触达渠道，需预先配置方可路由。
- **CRM 跟进通道（CRM_FollowUp_Channel）**：用于商机跟进开发的客户关系管理系统触达通道，需预先配置方可路由。
- **跟进状态（FollowUp_Status）**：商机在跟进通道中的处理状态，取值集合为「待路由」「已触达」「跟进中」「路由失败」四者之一且任一时刻唯一。
- **销售跟进剧本（Followup_Playbook）**：基于线索评分、买家画像、产品素材与来源广告生成的推荐跟进渠道、首轮话术、后续提醒、关键卖点与风险提示。
- **线索评分（Lead_Score）**：基于线索字段、来源广告、买家画像匹配度、互动行为与转化阶段计算的商机优先级评分。
- **买家回复（Buyer_Reply_Event）**：商机在跟进通道（企业 WhatsApp 或 CRM）中收到买家回应的可记录事件，承载精确到秒的回复时间与来源通道，用于判定该商机是否「已成功联络」。

### 业务结果指标术语

- **业务结果指标（Business_Outcome_Metric）**：对标竞品数字卖点的一组一等获客成效指标，包含单条有效询盘成本、客户有效联络率、各买家意向等级占比分布、投放到首条商机时长与客户资产归属/私域沉淀，由效果看板服务按统一口径计算，统一支持按平台（Meta、Google、TikTok）与时间范围（最近 1 至 365 天）维度计算。
- **有效线索（Qualified_Lead）**：达到「有效」判定口径的商机，判定口径为背调可信度评估达标或买家意向等级达到用户可配置的意向等级阈值；阈值由用户配置，缺省时采用系统默认阈值。
- **单条有效询盘成本（Cost_Per_Qualified_Lead）**：定义为「统计区间内花费 / 同区间有效线索数」；有效线索数为零时标记为「不可计算」。
- **客户有效联络率（Effective_Contact_Rate）**：定义为「已成功联络的商机数 / 商机总数」，已成功联络指商机已触达且已记录买家回复事件；商机总数为零时标记为「不可计算」。
- **各买家意向等级占比分布（Intent_Level_Distribution）**：对已分级商机按等级统计 L1/L2/L3/L4 各占比并突出展示「L3+L4 高意向占比」；已分级商机数为零时标记为「不可计算」。
- **投放到首条商机时长（Time_To_First_Opportunity）**：定义为某广告计划「首条商机采集时间」与「首次投放成功时间」之差值；该计划尚无商机时标记为「暂无商机」，用于支撑「当日投放当日见客资」的时效卖点。
- **客户资产归属与私域沉淀（Lead_Asset_Ownership）**：每条商机数据的数据所有权归属于其所属外贸商家客户，在商家账户名下持久留存且可导出，不因广告计划停投或重投而丢失。
- **客户行业调查报告（Industry_Survey_Report）**：基于背调结果、商机数据与产品素材，含行业分布、客户画像、商机意向等级分布、目标市场与竞争格局概览、获客行动建议等维度的报告，作为效果看板的可导出报告提供给用户。
- **商机清单（Opportunity_List）**：效果看板服务以列表形式呈现的当前商家账户名下全部商机，支持按意向等级/来源平台/跟进状态/时间范围筛选与排序，可导出为 Excel/CSV。
- **客户详情（Opportunity_Detail）**：单条商机的完整档案视图，含原始留资字段、留资质量校验标注、Gemini 背调补全字段与可信度评估、买家意向等级及变更轨迹、来源广告与采集时间、跟进状态与跟进剧本。
- **商机导出文件（Opportunity_Export）**：按当前筛选条件生成的可下载表格文件（Excel 或 CSV），含留资字段、背调补全字段、可信度评估、意向等级与来源信息，是系统面向商家的核心精准客户信息交付物。
- **商机数据对外 API（Opportunity_Data_API）**：面向后续自有 CRM 系统或第三方系统的标准化读取接口，使外部系统可按商家维度拉取或增量同步商机档案（留资字段、背调补全字段、可信度评估、意向等级、跟进状态、来源信息）；通过 API 凭证鉴权、受数据隔离约束、支持分页与按更新时间增量拉取。
- **API 凭证（API_Credential）**：颁发给外部系统调用商机数据对外 API 的鉴权凭证（如 API Key 或 OAuth 客户端凭据），与商家绑定、可签发与吊销，并按凭据安全与日志脱敏范式管理。

### 高级投放能力术语（本期实现）

- **平台扩展能力包（Platform_Extensions）**：在统一广告对象模型之上，按平台命名空间暴露各平台独有或高级能力的机制；扩展能力仅在对应平台凭据已配置且该平台支持时可用。
- **扩展能力调用网关（Extension_Gateway）**：统一受理对平台扩展能力的调用、校验目标平台是否支持所请求扩展能力、并在不支持或凭据缺失时返回相应错误或执行降级的子模块。
- **Advantage+ 系列（AdvantagePlus_Campaign）**：Meta 提供的 AI 全自动投放系列类型（含 Advantage+ Shopping、Advantage+ App、Advantage+ Audience）。
- **硬控制（Hard_Control）**：Advantage+ 系列中由用户强制约束投放范围的控制项，包括地域、语言、最低年龄、排除条件与特殊广告类别。
- **定向建议（Targeting_Suggestion）**：平台基于种子条件向用户推荐的可选受众定向条件。
- **商品流（Product_Feed）**：对各平台商品目录（Meta Catalog、Google Merchant Center、TikTok Catalog）的统一抽象。
- **商品集（Product_Set）**：商品流中按规则筛选出的商品子集，作为动态商品广告或购物广告的投放单位。
- **动态商品广告（Dynamic_Product_Ad）**：依据用户行为从商品集中自动选品展示的广告形式，含购物广告。
- **商品流服务（Catalog_Service）**：负责商品流建立、与各平台商品目录同步及同步状态管理的子模块。
- **Performance Max 系列（PerformanceMax_Campaign）**：Google 提供的跨全版位 AI 自动投放系列类型。
- **资产组（Asset_Group）**：Performance Max 系列中承载文字、图片、视频等多类资产组合的投放单元。
- **出价策略（Bidding_Strategy）**：广告组所采用的出价优化方式，统一枚举包括 Target CPA、Target ROAS、Maximize Conversions、Maximize Conversion Value、Maximize Clicks、Manual CPC，各平台按其支持集校验。
- **Spark Ads**：TikTok 提供的将自然原生视频帖加热为广告并将广告效果归因到该自然帖的广告形式，受账户级数量上限约束。
- **A/B 实验（AB_Experiment）**：对 Meta Split Test、Google Experiments、TikTok Split Test 的统一抽象。
- **实验服务（Experiment_Service）**：负责 A/B 实验创建、分组与结果读取的子模块。
- **投前预估（PreLaunch_Estimate）**：对 Meta Reach/Delivery Estimate、Google Reach Forecasting 的统一抽象，在投放前提供预估触达与询盘量区间。
- **预估服务（Estimate_Service）**：负责在投放前向各平台请求并归一化投前预估结果的子模块。
- **消息广告（Messaging_Ad）**：点击后直接打开即时通讯会话的广告类型，含 Click-to-WhatsApp（CTWA）与 Click-to-Messenger。
- **AI 创意生成（AI_Creative_Generation）**：对 TikTok Symphony API、Google 生成式资产组、Meta 动态创意的统一入口，依据产品素材生成多语言创意变体。
- **创意服务（Creative_Service）**：负责调用各平台 AI 创意生成能力、管理生成创意变体的子模块。
- **离线/CRM 转化通道（Offline_Conversion_Channel）**：通过服务端方式回传线下或 CRM 转化数据的转化追踪通道。
- **广告版位（Placement）**：统一广告对象模型在广告组层级的字段，表示广告在目标平台上展示的位置集合，配置方式在「自动版位」与「手动版位」二者中有且仅有一个生效。
- **自动版位（Automatic_Placement）**：由目标平台投放系统自动选择并优化全场景版位组合的配置方式。
- **手动版位（Manual_Placement）**：由用户从目标平台支持的版位集合中显式选择版位的配置方式，不支持的所选版位被标记为该平台不适用。

## Requirements

### 第一部分 · 核心主线（本期实现）

> 以下需求 1 至需求 21 为本期核心主线，对标竞品五步获客法。

### 需求 1：平台凭据与密钥配置化管理

**User Story:** 作为系统管理员，我希望以配置化、可后填的方式管理各平台的密钥与凭据，以便在尚未取得 API 密钥时也能完成系统部署，并在取得密钥后安全填入。

#### 验收标准

1. THE 凭据管理器 SHALL 为每个支持的平台（Meta、Google、TikTok）与底层生成式 AI（Gemini）提供独立的凭据配置项，每个配置项的状态取值仅为「未填入」与「已填入」，且当且仅当该项所有必填凭据均已提交并通过校验时其状态为「已填入」，否则为「未填入」。
2. WHEN 系统管理员通过配置接口提交某凭据且该凭据通过校验，THE 凭据管理器 SHALL 以加密方式存储该凭据，并在存储成功后将对应配置项状态更新为「已填入」。
3. THE 凭据管理器 SHALL 在任何日志、错误信息与接口响应输出中以脱敏占位符替代凭据明文值，使输出内容不包含任何完整凭据明文。
4. WHERE 某平台的凭据配置项状态为「未填入」，THE 广告系统 SHALL 将该平台的投放相关功能标记为不可用，并保持其余状态为「已填入」平台的功能正常运行。
5. IF 某平台凭据缺失而用户尝试使用该平台功能，THEN THE 广告系统 SHALL 返回「该平台凭据未配置」的错误提示并保持其余平台功能正常运行。
6. THE 凭据管理器 SHALL 拒绝以硬编码方式接收凭据，仅接受通过配置接口提交的凭据值。
7. IF 系统管理员提交的凭据值为空或不符合该平台凭据要求，THEN THE 凭据管理器 SHALL 拒绝保存该凭据、返回包含不符合项的校验错误，并保持该配置项原有状态不变。
8. IF 凭据加密或存储过程失败，THEN THE 凭据管理器 SHALL 返回包含失败原因的错误提示、不持久化任何明文凭据值，并保持该配置项原有状态不变。

### 需求 2：Meta 平台代客户授权

**User Story:** 作为系统管理员，我希望通过 Meta 官方的 System User 与 on-behalf-of 机制代客户管理广告账户，以便客户保留自身 Business Manager 所有权的同时由系统统一投放。

#### 验收标准

1. WHEN 系统管理员发起 Meta 客户授权流程且授权成功，THE 账户授权中心 SHALL 基于 System User token 与 on-behalf-of 方式建立对客户 Business Manager 的代管理关系，并将该账户授权状态置为「有效」。
2. WHEN Meta 客户授权成功，THE 账户授权中心 SHALL 记录该 Meta 客户授权的所属客户标识、授权范围与精确到秒的令牌有效期。
3. WHERE 系统采用两层 Business Manager 结构进行规模化管理，THE 账户授权中心 SHALL 支持将客户账户挂载到指定的下层 Business Manager，且挂载数量受 Meta 平台规定的上限约束。
4. WHILE 某 Meta 客户授权处于「有效」状态，THE 账户授权中心 SHALL 至少每 15 分钟检测一次该授权是否仍然有效。
5. WHEN 账户授权中心检测到客户在其 Business Manager 中撤销授权，THE 账户授权中心 SHALL 在检测到授权失效后的 5 分钟内将该客户的 Meta 账户状态更新为「授权已撤销」。
6. IF Meta System User token 调用返回授权失效错误，THEN THE 账户授权中心 SHALL 将受影响账户标记为「需重新授权」并记录精确到秒的失败时间。
7. IF Meta 客户授权流程建立失败，THEN THE 账户授权中心 SHALL 不建立代管理关系、返回包含失败原因的错误提示，并保持该账户授权状态为「未授权」。

### 需求 3：Google Ads 平台代客户授权

**User Story:** 作为系统管理员，我希望通过 Google MCC 经理账号代客户管理 Google Ads 账户，以便统一管理客户的 Google 与 YouTube 广告投放。

#### 验收标准

1. WHEN 系统管理员发起 Google 客户授权流程且挂载成功，THE 账户授权中心 SHALL 通过 MCC 经理账号将客户账户挂载于其下，并将该账户授权状态置为「有效」。
2. WHEN Google 客户账户挂载成功，THE 账户授权中心 SHALL 记录该 Google 客户账户的 MCC 关联关系与精确到秒的 OAuth 令牌有效期。
3. WHILE Google OAuth 令牌距上次使用超过 80 天且未达到 90 天，THE 账户授权中心 SHALL 对该令牌执行保活刷新操作，并在刷新成功后更新该令牌的上次使用时间。
4. IF Google OAuth 令牌距上次使用达到 90 天，THEN THE 账户授权中心 SHALL 将该令牌标记为「需重新授权」并向系统管理员发出预警。
5. WHEN 账户授权中心检测到客户解除与 MCC 的关联，THE 账户授权中心 SHALL 将该客户的 Google 账户状态更新为「授权已撤销」。
6. IF MCC 挂载请求被拒绝或客户在 30 天内未接受挂载邀请，THEN THE 账户授权中心 SHALL 将该账户状态置为「需重新授权」并向系统管理员返回包含失败原因的提示。
7. IF Google OAuth 或 MCC 调用返回授权失效错误，THEN THE 账户授权中心 SHALL 将受影响账户标记为「需重新授权」并记录精确到秒的失败时间。

### 需求 4：TikTok 平台代客户授权（差异化能力）

**User Story:** 作为系统管理员，我希望通过 TikTok Business Center Agency 模式与每账户 OAuth 2.0 授权代客户管理 TikTok 广告账户，以便在 Meta 与 Google 之外差异化提供 TikTok 投放。

#### 验收标准

1. WHEN 系统管理员发起 TikTok 客户授权流程且授权完成，THE 账户授权中心 SHALL 通过 Business Center Agency 关系与每账户 OAuth 2.0 授权建立代管理关系，并将该账户授权状态置为「有效」。
2. WHEN TikTok 客户授权完成，THE 账户授权中心 SHALL 记录该 TikTok 客户账户的所属客户标识、授权范围、Business Center 关联关系，以及访问令牌与刷新令牌各自精确到秒的有效期。
3. WHEN 账户授权中心检测到 TikTok OAuth 访问令牌已过期，THE 账户授权中心 SHALL 使用刷新令牌获取新的访问令牌并更新其有效期。
4. IF TikTok 刷新令牌已失效，THEN THE 账户授权中心 SHALL 将受影响账户标记为「需重新授权」、保留已记录的授权关联关系，并向系统管理员发出预警。
5. IF TikTok 客户授权流程失败，THEN THE 账户授权中心 SHALL 不建立代管理关系、返回包含失败原因的错误提示，并保持该账户授权状态为「未授权」。
6. WHEN 账户授权中心检测到客户解除 Business Center Agency 关系，THE 账户授权中心 SHALL 将该客户的 TikTok 账户状态更新为「授权已撤销」。

### 需求 5：令牌生命周期与状态监控

**User Story:** 作为系统管理员，我希望账户授权中心统一监控所有平台令牌的状态并在异常前预警，以便及时处理避免投放中断。

#### 验收标准

1. THE 账户授权中心 SHALL 为每个平台账户记录令牌状态，状态取值为「有效」「即将过期」「已过期」「需重新授权」「授权已撤销」五者之一，且任一时刻每个平台账户有且仅有一个状态。
2. WHILE 某令牌剩余有效期处于 0 至 7 天之间（含 7 天、不含 0），THE 账户授权中心 SHALL 将该令牌状态置为「即将过期」并向系统管理员发出包含平台、账户标识与剩余天数的预警，且对同一令牌的同一预警仅发送一次。
3. WHEN 某令牌到期且未被刷新，THE 账户授权中心 SHALL 将该令牌状态置为「已过期」。
4. WHEN 令牌刷新成功，THE 账户授权中心 SHALL 更新该令牌的有效期、将状态置为「有效」并将该令牌的连续刷新失败计数复位为 0。
5. IF 令牌刷新在连续窗口内失败达到 3 次，THEN THE 账户授权中心 SHALL 将该令牌状态置为「需重新授权」、停止后续自动刷新尝试、记录精确到秒的失败时间并通知系统管理员。
6. IF 预警通知发送失败，THEN THE 账户授权中心 SHALL 记录失败原因、保持该令牌状态不变并在下一监控周期重试发送。
7. THE 账户授权中心 SHALL 向系统管理员提供所有平台账户的授权状态汇总视图，视图包含平台、账户标识、当前状态与令牌剩余有效期。

### 需求 6：凭据安全与日志脱敏

**User Story:** 作为系统管理员，我希望所有平台凭据均被安全保护，以便满足安全合规要求并防止凭据泄露。

#### 验收标准

1. THE 广告系统 SHALL 对所有平台凭据在存储时进行加密，且任何持久化介质均不保存凭据明文。
2. WHEN 系统在日志、错误信息或接口响应中输出包含凭据的内容，THE 广告系统 SHALL 对凭据值进行脱敏处理，使暴露的明文不超过末位 4 位，其余字符以占位符替代。
3. WHEN 系统读取凭据用于平台调用，THE 凭据管理器 SHALL 在内存中解密使用且不将明文写入持久化日志。
4. WHEN 凭据使用结束，THE 凭据管理器 SHALL 释放内存中的凭据明文。
5. IF 检测到与已存储凭据匹配的明文值将被输出到日志、错误信息或接口响应，THEN THE 广告系统 SHALL 拦截该输出并以脱敏占位符替代后再输出。

### 需求 7：多角色权限管理

**User Story:** 作为系统管理员，我希望区分外贸商家客户、平台投手与系统管理员的权限，以便各角色只能访问其职责范围内的功能与数据。

#### 验收标准

1. WHEN 系统管理员发起对平台凭据、账户池或角色权限的创建、查看、修改或删除操作，THE 广告系统 SHALL 允许该操作执行。
2. WHEN 平台投手发起对已分配给其负责商家的广告计划与商机的创建、查看、修改或删除操作，THE 广告系统 SHALL 允许该操作执行，并拒绝其对未分配商家广告计划与商机的访问。
3. WHEN 外贸商家客户发起对其自身账户名下产品素材、商机与数据的访问，THE 广告系统 SHALL 允许该访问，并拒绝其对其他账户数据的访问。
4. IF 某角色尝试访问超出其权限范围的功能或数据，THEN THE 广告系统 SHALL 拒绝该访问、返回「权限不足」的错误并不执行任何创建、修改或删除操作（保持目标数据状态不变）。
5. IF 未认证用户尝试访问任何受保护功能或数据，THEN THE 广告系统 SHALL 拒绝该访问并返回「未认证」的错误。
6. WHEN 某角色发生越权访问尝试，THE 广告系统 SHALL 记录包含角色标识、目标资源标识与精确到秒的时间的审计记录。

### 需求 8：统一广告对象模型与三级广告计划创建

**User Story:** 作为平台投手，我希望在统一的界面与数据模型下以「广告系列→广告组→广告」三级结构创建并管理所有平台的广告计划，以便无需了解各平台字段差异即可发起对外投放。

#### 验收标准

1. THE 统一广告模型层 SHALL 以「广告系列→广告组→广告」三级结构表达所有支持平台（Meta、Google、TikTok）的广告对象，且每个子级对象有且仅有一个父级对象。
2. WHEN 投手提交包含名称、投放目标与所属平台的广告系列创建请求，THE 广告系统 SHALL 创建广告系列、记录其投放目标与所属平台并返回唯一标识，其中名称长度为 1 至 255 个字符。
3. WHEN 投手在已存在的广告系列下提交广告组创建请求，THE 广告系统 SHALL 创建关联到该广告系列的广告组并返回唯一标识；WHEN 投手在已存在的广告组下提交广告创建请求，THE 广告系统 SHALL 创建关联到该广告组的广告并返回唯一标识。
4. WHEN 投手在统一模型中创建广告对象，THE 统一广告模型层 SHALL 在 5 秒内将统一字段映射为目标平台的原生字段。
5. WHERE 某统一字段在目标平台不存在对应原生字段但存在平台默认值，THE 统一广告模型层 SHALL 对该字段应用该平台默认值；WHERE 不存在对应原生字段且无平台默认值，THE 统一广告模型层 SHALL 将该字段标记为该平台不适用。
6. IF 投手尝试在不存在的父级对象下创建子级对象，THEN THE 广告系统 SHALL 返回「父级对象不存在」的错误、不创建子级对象并保持父级对象状态不变。
7. IF 广告计划必填字段缺失或统一字段映射到目标平台时校验失败（包括取值越界、格式不符），THEN THE 统一广告模型层 SHALL 返回包含字段名与失败原因分类的校验错误、不提交至目标平台并保留已输入字段值。
8. IF 单个广告系列下的广告组数量或单个广告组下的广告数量超过 5000，THEN THE 广告系统 SHALL 拒绝创建并返回「数量超过上限」的错误。
9. THE 统一广告模型层 SHALL 提供面向 LinkedIn 的扩展位，使第二期可在无需修改既有 Meta、Google、TikTok 平台字段映射定义的前提下新增平台适配器。

### 需求 9：AI 自动建广告与投放优化

**User Story:** 作为外贸商家客户与平台投手，我希望在商家提供成品广告素材与产品定位描述后，系统自动推导买家画像（国家/地区 + 行业 + 职位）、自动生成多平台广告计划（草案中素材为对成品素材的挂载/引用，不含创意设计制作）、以「商机成效最大化」自动优化并自动投放，资深投手仅在投放后按需介入优化，以便实现前三步全自动获客。

#### 验收标准

1. WHEN 商家提交产品定位描述与成品广告素材且未显式指定买家画像且底层生成式 AI 凭据配置项状态为「已填入」，THE AI 辅助建广告引擎 SHALL 依据产品定位描述与成品素材自动推导包含国家/地区、行业、职位维度的买家画像，并将该画像的来源标记为「AI 自动推导」；WHERE 投手显式指定买家画像，THE AI 辅助建广告引擎 SHALL 采用人工指定画像并将来源标记为「人工指定」。
2. WHEN 系统接收到包含成品广告素材与买家画像维度（国家/地区、行业、职位，可由 AI 自动推导或人工指定）的广告计划生成请求且底层生成式 AI 凭据配置项状态为「已填入」，THE AI 辅助建广告引擎 SHALL 自动生成包含 Meta、Google、TikTok 各平台广告系列、广告组、广告、受众定向、预算、素材挂载与留资表单建议的广告计划草案，并以「商机成效最大化（单位花费所获有效商机数最大化）」为目标生成投放与出价建议；草案中的素材项为对已上传成品素材的引用，引擎不对素材内容做创意设计或改写。
3. WHERE 人工审核模式关闭（系统默认），THE AI 辅助建广告引擎 SHALL 在草案生成后自动将其确认状态置为「已确认」并直接进入需求 8、需求 10、需求 12、需求 13 定义的广告计划创建与投放流程，无需人工逐次确认。
4. THE 广告系统 SHALL 支持人工审核模式按全局默认与单个商家覆盖两级配置，单个商家未覆盖时采用全局默认（默认关闭即全自动档），且同一商家任一时刻有且仅有一个生效档位；切换档位不影响已投放的广告计划。
5. WHERE 人工审核模式开启，THE AI 辅助建广告引擎 SHALL 将新生成的广告计划草案确认状态置为「待确认」，且确认状态为「待确认」的广告计划草案不得发布或投放，直至投手确认后置为「已确认」并进入投放流程。
6. IF 人工审核模式开启且有人尝试发布或投放确认状态为「待确认」的广告计划草案，THEN THE 广告系统 SHALL 拒绝该操作并提示该草案尚未确认。
7. WHERE 底层生成式 AI 凭据配置项状态为「未填入」，THE 广告系统 SHALL 将 AI 自动建广告与投放优化能力标记为不可用并保持其余功能正常运行，而非中断。
8. IF 生成广告计划草案所需的成品广告素材或买家画像维度（国家/地区、行业、职位）缺失，THEN THE AI 辅助建广告引擎 SHALL 返回包含全部缺失项名称的错误并不生成广告计划草案。
9. WHEN 系统对已投放广告计划执行优化分析或投手发起优化分析请求，THE AI 辅助建广告引擎 SHALL 基于数据回传服务提供的曝光、点击、转化、花费与 ROI 指标，以「商机成效最大化」为目标生成包含调整项、调整前取值、调整后建议取值与预期变化量的优化建议。
10. WHERE 目标平台提供官方 MCP 连接器，THE AI 辅助建广告引擎 SHALL 优先通过 MCP 连接器接入该平台的 AI 优化能力，否则通过该平台官方 Marketing/Ads API 直连获取优化所需数据。
11. WHERE 自动优化已开启，THE AI 辅助建广告引擎 SHALL 在预先设定的预算与出价调整上下限范围内自动应用优化调整，并记录每次调整的调整项、调整前后取值与精确到秒的调整时间。
12. IF 优化所需的指标数据缺失或拉取失败，THEN THE AI 辅助建广告引擎 SHALL 不生成优化建议并提示数据不可用。
13. IF 自动优化调整超出预先设定的授权范围，THEN THE AI 辅助建广告引擎 SHALL 不应用该调整并转为向资深投手请求人工确认。
14. IF 自动优化调整应用失败，THEN THE AI 辅助建广告引擎 SHALL 保留调整前的原配置并记录失败原因。
15. THE AI 辅助建广告引擎 SHALL 以「有效高意向商机数」（即背调可信度达标或买家意向等级达到阈值的商机数，见需求 15、需求 16）为投放优化的首要目标，而非以曝光量或点击量为优化目标，并在生成投放与出价建议时优先分配预算给历史回流有效高意向商机占比更高的受众与版位组合。
16. WHEN 已投放计划累计回流足量商机，THE AI 辅助建广告引擎 SHALL 基于已回流的高意向商机特征生成相似扩展受众建议与低意向人群排除建议，用以提升后续回流商机的质量与购买意向。

### 需求 10：受众定向设置

**User Story:** 作为平台投手，我希望为广告组设置受众定向条件，以便将广告精准投放给买家画像所描述的目标买家。

#### 验收标准

1. THE 广告系统 SHALL 支持在广告组上设置核心定向维度国家/地区、行业、职位，并支持年龄、性别、兴趣、行为定向条件，其中年龄取值为 13 至 65 之间的整数并含「65 岁及以上」选项，性别取值限定为「男」「女」「不限」。
2. THE 广告系统 SHALL 支持在广告组上配置自定义受众与相似受众。
3. WHEN 投手保存受众定向设置且全部定向条件通过校验，THE 平台适配器 SHALL 将定向条件转换为目标平台的原生定向参数并持久化该定向设置。
4. WHERE 目标平台不支持某定向维度，THE 统一广告模型层 SHALL 将该维度标记为该平台不适用并向投手返回包含该维度名称的不适用提示。
5. THE 统一广告模型层 SHALL 为 LinkedIn 预留职位、公司、行业定向维度的扩展位。
6. IF 受众定向条件组合导致目标平台估算受众规模低于该平台可投放的最小受众规模阈值（含估算结果为零），THEN THE 广告系统 SHALL 向投手返回「受众规模过小」的提示并不将该定向设置提交至目标平台。
7. IF 受众定向条件转换为目标平台原生定向参数时校验失败（包括取值超出允许范围或维度取值非法），THEN THE 平台适配器 SHALL 返回包含定向维度名称与失败原因的校验错误并不保存该定向设置。
8. THE 广告系统 SHALL 支持在广告组上配置排除定向与负向受众，用以滤除低购买意向人群（如学生、求职者、与目标行业/职位不符的人群），以提升回流商机的购买意向。
9. WHERE 已存在历史高意向商机数据，THE 广告系统 SHALL 支持以高意向商机为种子创建相似受众，用以扩展触达与目标买家画像相似的高意向人群。

### 需求 11：成品广告素材上传与平台合规校验

**User Story:** 作为外贸商家客户，我希望上传**已制作完成的成品广告素材**（广告视频、图片、PDF 等）并由系统统一存储、做平台合规校验与管理，以便平台投手直接据此挂载投放，且单份素材失败不影响其余素材。

#### 验收标准

1. WHEN 商家上传成品广告视频、图片、PDF、轮播或其他成品广告素材，THE 素材服务 SHALL 在单个文件大小不超过 500MB、轮播素材包含 2 至 10 个子素材的范围内存储该素材、生成唯一素材标识、记录来源类型与精确到秒的上传时间并返回上传成功指示。
2. IF 上传素材的格式、尺寸、时长或文件大小不符合目标平台的成品广告投放要求或超出系统上限，THEN THE 素材服务 SHALL 拒绝该素材、不予存储并返回包含每一项具体不符合项的错误说明。
3. IF 某份素材上传因网络中断或存储失败而未完成，THEN THE 素材服务 SHALL 不保留不完整素材、隔离该份素材并保留其余已成功上传的素材，而非中断整批上传。
4. WHEN 投手将成品素材关联（挂载/引用）到广告，THE 平台适配器 SHALL 将该成品素材上传或引用至目标平台，而不对素材内容做创意改写或重新设计。
5. IF 素材上传或引用至目标平台失败，THEN THE 平台适配器 SHALL 保留该素材与广告的关联记录以待重试并向用户返回包含失败原因的错误说明。
6. THE 素材服务 SHALL 允许用户查看、复用并删除其自身账户已上传的素材。
7. IF 用户尝试删除当前正被广告引用的素材，THEN THE 素材服务 SHALL 拒绝删除并提示该素材正在被引用。

### 需求 12：预算、出价与投放排期设置

**User Story:** 作为平台投手，我希望为广告组设置预算、出价方式与投放排期，以便控制投放成本与节奏。

#### 验收标准

1. THE 广告系统 SHALL 支持在广告组上设置日预算与总预算，预算取值范围为 0.01 至 999,999,999.99（保留两位小数）。
2. THE 广告系统 SHALL 支持设置目标平台所提供的基础出价方式。
3. WHEN 投手设置投放排期的开始时间与结束时间且结束时间不早于开始时间，THE 广告系统 SHALL 保存该投放排期。
4. IF 投放排期的结束时间早于开始时间，THEN THE 广告系统 SHALL 返回「排期时间无效」的校验错误并不保存排期。
5. IF 预算值小于 0.01 或大于 999,999,999.99，THEN THE 广告系统 SHALL 返回「预算超出允许范围」的校验错误并不保存。
6. IF 设置的日预算大于总预算，THEN THE 广告系统 SHALL 返回「日预算不得大于总预算」的校验错误并不保存。
7. IF 投手设置的出价方式不在目标平台支持的出价方式范围内，THEN THE 广告系统 SHALL 返回「出价方式不受支持」的校验错误并不保存。

### 需求 13：广告投放到各平台

**User Story:** 作为外贸商家客户与平台投手，我希望已确认的广告计划（默认由 AI 自动确认）自动投放到 Meta、Google 或 TikTok，以便代商家对外发布广告并实现当日投放当日获客。

#### 验收标准

1. WHEN 系统对确认状态为「已确认」的广告计划发起投放且目标平台账户授权状态为「有效」，THE 平台适配器 SHALL 通过目标平台官方 API 将广告计划提交至该平台并将投放状态置为「提交中」；该投放可由 AI 在草案自动确认后自动触发（人工审核模式关闭时），亦可由投手手动触发（人工审核模式开启时）。
2. WHEN 平台在 30 秒内返回投放成功，THE 广告系统 SHALL 记录平台返回的广告对象标识并将投放状态置为「已提交」。
3. IF 目标平台返回投放失败，THEN THE 广告系统 SHALL 记录失败原因、将投放状态置为「投放失败」并向投手返回包含失败原因的错误提示。
4. IF 目标平台账户授权状态为「需重新授权」或「授权已撤销」，THEN THE 广告系统 SHALL 阻止投放、保持投放状态为「未提交」并提示先恢复授权。
5. IF 投放请求在 30 秒内未收到平台响应，THEN THE 广告系统 SHALL 将投放状态置为「投放超时」并向投手返回超时提示。
6. IF 对同一广告计划重复发起投放请求且上一次请求处于「提交中」状态，THEN THE 广告系统 SHALL 拒绝本次重复提交并提示该计划正在投放中。

### 需求 14：高门槛留资表单与线索回流

**User Story:** 作为外贸商家客户，我希望买家通过高门槛留资表单（公司名、姓名、电话、邮箱必填）提交信息并自动回流为商机，以便筛掉无效流量、只接收有跟进价值的高质量商机。

#### 验收标准

1. THE 线索收集服务 SHALL 支持配置高门槛留资表单，并将公司名、姓名、电话、邮箱设为必填字段，表单字段项数量为 1 至 30 个，其余字段可标记为必填或选填。
2. WHEN 投手将高门槛留资表单关联到广告且关联成功，THE 平台适配器 SHALL 将表单配置提交至目标平台并将该表单状态置为「已关联」。
3. IF 表单配置提交至目标平台失败，THEN THE 平台适配器 SHALL 返回包含失败原因的错误并将该表单状态置为「关联失败」。
4. IF 买家提交的留资表单缺失公司名、姓名、电话或邮箱中的任一必填项，THEN THE 线索收集服务 SHALL 拒绝该留资并不将其回流为商机。
5. WHEN 买家提交通过必填校验的高门槛留资表单，THE 线索收集服务 SHALL 在 15 分钟内将该线索回流并升格为商机存储到系统中。
6. THE 线索收集服务 SHALL 记录每条商机的来源平台、来源广告标识与精确到秒的采集时间。
7. IF 线索回流过程中出现重复线索，THEN THE 线索收集服务 SHALL 按来源平台线索标识去重并保留最早采集的单条记录。
8. IF 线索回流或存储失败，THEN THE 线索收集服务 SHALL 记录失败原因并保留原始线索数据以供重试。
9. THE 线索收集服务 SHALL 对每条回流留资执行格式与有效性校验，包括邮箱格式校验、电话号码格式与国家区号校验、以及对一次性/临时邮箱域名与明显无效占位值（如全 0 电话、测试字样）的识别。
10. IF 留资的邮箱或电话格式无效、或命中一次性邮箱域名或无效占位值，THEN THE 线索收集服务 SHALL 将该留资标记为「低质量/疑似无效」并将其与正常高质量商机区分存储，不计入有效线索。
11. THE 线索收集服务 SHALL 对疑似机器人或自动化批量提交执行反作弊过滤（包括同一来源短时间高频提交、字段内容雷同的批量提交识别），并将命中项标记为「疑似作弊」且不回流为有效商机。
12. WHERE 留资包含公司名或公司邮箱域名，THE 线索收集服务 SHALL 尝试基于公司名与企业邮箱域名做企业身份初判，并将「疑似真实企业」与「疑似个人/免费邮箱」标注记录在商机上，供后续背调与分级使用，以提升回流商机的购买意向判定精度。

### 需求 15：Gemini AI 客户背调验证

**User Story:** 作为外贸商家客户，我希望系统对回流商机调用 Google Gemini AI 做客户背景调查并补全可验证信息，以便获得每条商机的可信度评估与背调摘要，从而判断商机质量。

#### 验收标准

1. THE 凭据管理器 SHALL 为 Gemini 背调服务提供独立的凭据配置项，其状态取值仅为「未填入」与「已填入」，并对该凭据按加密存储与日志脱敏的方式管理（与需求 1、需求 6 一致）。
2. WHEN 线索收集服务回流并存储一条新商机且 Gemini 背调服务凭据配置项状态为「已填入」，THE Gemini 背调服务 SHALL 对该商机发起客户背景调查，补全并校验公司、地区、行业、职位、网站与社媒可验证信息，输出包含校验后客户信息字段、可信度评估与背调摘要的背调结果，并记录精确到秒的背调完成时间。
3. WHERE Gemini 背调服务凭据配置项状态为「未填入」，THE 广告系统 SHALL 将背调能力标记为不可用、正常存储该商机并保持其余功能正常运行，而非中断商机存储。
4. IF Gemini 背调服务调用失败，THEN THE Gemini 背调服务 SHALL 记录失败原因、保留该商机的原始留资数据、将该商机的背调状态置为「背调失败」并保留以供重试。
5. IF Gemini 背调服务返回的客户信息与商机原始留资数据存在冲突，THEN THE Gemini 背调服务 SHALL 同时保留原始留资值与背调返回值并在背调结果中将该字段标注为「待核实」。

### 需求 16：商机智能分级（买家意向等级 L1-L4）

**User Story:** 作为平台投手，我希望系统基于背调可信度评估、买家画像匹配度与行为数据对每条商机计算买家意向等级（L1-L4），以便优先跟进 L3、L4 高意向商机。

#### 验收标准

1. WHEN 某商机的背调结果生成或其行为数据更新，THE 商机分级引擎 SHALL 基于背调可信度评估、买家画像匹配度与行为数据（表单完整度、留资字段质量、来源广告）计算该商机的买家意向等级，等级取值为「L1」「L2」「L3」「L4」之一。
2. THE 商机分级引擎 SHALL 为每个商机维护有且仅有一个买家意向等级，其取值集合为「L1」「L2」「L3」「L4」「未分级」且任一时刻唯一，其中 L4 为最高、L1 为最低。
3. IF 商机分级所依据的背调结果、买家画像匹配度或行为数据缺失，THEN THE 商机分级引擎 SHALL 将该商机的买家意向等级置为「未分级」并记录导致无法分级的缺失项名称。
4. WHEN 投手请求按买家意向等级排序或筛选商机，THE 广告系统 SHALL 按所选等级条件返回商机列表，排序时 L4 优先级高于 L3、L3 高于 L2、L2 高于 L1。
5. WHEN 某商机的背调结果、买家画像匹配度或行为数据发生变更，THE 商机分级引擎 SHALL 重新计算该商机的买家意向等级并以重新计算后的等级覆盖原等级。
6. THE 广告系统 SHALL 记录每次买家意向等级变更的变更前等级、变更后等级与精确到秒的变更时间。

### 需求 17：商机跟进、企业 WhatsApp 直连与销售跟进剧本

**User Story:** 作为外贸商家客户，我希望高意向商机能自动或手动路由进入企业 WhatsApp 与/或 CRM 跟进通道并获得销售跟进剧本，以便业务团队及时且有章法地触达开发商机，且在通道异常时不丢失商机。

#### 验收标准

1. THE 跟进路由服务 SHALL 为每个商机维护有且仅有一个跟进状态，其取值集合为「待路由」「已触达」「跟进中」「路由失败」且任一时刻唯一。
2. WHERE 企业 WhatsApp 通道或 CRM 跟进通道已配置，THE 跟进路由服务 SHALL 支持将商机自动或手动路由进入企业 WhatsApp 通道与/或 CRM 跟进通道。
3. WHEN 某商机的买家意向等级达到用户设定的自动路由阈值且企业 WhatsApp 通道已配置，THE 跟进路由服务 SHALL 自动将该商机路由进入企业 WhatsApp 通道、将其跟进状态置为「已触达」并记录精确到秒的触达时间。
4. WHEN 用户对某商机手动发起跟进路由请求且目标跟进通道已配置，THE 跟进路由服务 SHALL 将该商机路由进入所选跟进通道、将其跟进状态置为「已触达」并记录精确到秒的触达时间。
5. WHEN 跟进路由服务成功路由某商机，THE 跟进路由服务 SHALL 基于线索评分、买家画像、产品素材与来源广告生成包含推荐跟进渠道、首轮话术、后续提醒、关键卖点与风险提示的销售跟进剧本。
6. IF 企业 WhatsApp 通道或所选 CRM 通道未配置，THEN THE 跟进路由服务 SHALL 返回「跟进通道未配置」的错误、保留该商机数据并将其跟进状态保持为「待路由」。
7. IF 商机路由进入跟进通道失败，THEN THE 跟进路由服务 SHALL 记录失败原因、将该商机跟进状态置为「路由失败」并保留该商机数据以待重试，而非丢失该商机。

### 需求 18：投放数据实时回传

**User Story:** 作为平台投手，我希望实时获取各平台的投放数据，以便监控广告效果并支撑 AI 优化。

#### 验收标准

1. THE 数据回传服务 SHALL 从 Meta、Google、TikTok 三个平台分别拉取曝光、点击、转化、花费原生指标。
2. THE 数据回传服务 SHALL 将 ROI 指标计算为转化价值与花费之比。
3. IF 某广告对象的花费为零，THEN THE 数据回传服务 SHALL 将该广告对象的 ROI 标记为「不可计算」。
4. THE 数据回传服务 SHALL 将各平台原生指标归一化为统一口径的指标字段。
5. WHILE 系统处于运行状态，THE 数据回传服务 SHALL 每达到 15 分钟发起一轮新的指标拉取。
6. WHEN 平台指标数据更新，THE 数据回传服务 SHALL 在 15 分钟内将更新反映到系统中对应广告对象的指标。
7. IF 某平台指标拉取失败，THEN THE 数据回传服务 SHALL 记录失败原因、保留该平台上一次成功拉取的指标数据并继续拉取其余平台。

### 需求 19：转化追踪

**User Story:** 作为外贸商家客户，我希望配置转化追踪，以便衡量广告带来的转化效果。

#### 验收标准

1. THE 广告系统 SHALL 支持用户配置目标平台的转化追踪机制，包括 Pixel、转化事件与 Events API，且单次配置最多支持 50 个转化事件定义。
2. WHEN 用户保存通过校验的转化追踪配置，THE 平台适配器 SHALL 在 60 秒内将转化事件定义提交至目标平台。
3. WHEN 目标平台返回转化事件定义提交成功，THE 广告系统 SHALL 记录平台返回的转化追踪对象标识并将该配置状态置为「已生效」。
4. IF 目标平台返回转化事件定义提交失败，THEN THE 平台适配器 SHALL 记录失败原因、将该配置状态置为「提交失败」，并保留用户已保存的配置内容。
5. WHEN 平台回传转化事件，THE 数据回传服务 SHALL 按来源平台事件标识将该转化事件关联到对应的广告对象。
6. IF 回传的转化事件无法关联到系统中任一广告对象，THEN THE 数据回传服务 SHALL 将该转化事件记录为「未匹配」状态并保留其原始回传数据。
7. IF 转化追踪配置校验失败，THEN THE 广告系统 SHALL 返回包含具体失败字段名与失败原因的校验错误，并不将该配置提交至目标平台。

### 需求 20：广告审核状态同步

**User Story:** 作为平台投手，我希望同步各平台的广告审核状态，以便及时了解广告是否可正常投放。

#### 验收标准

1. THE 广告系统 SHALL 每 15 分钟从各平台拉取每个广告对象的审核状态，并将其归一化为「审核中」「审核通过」「审核被拒绝」三者之一。
2. WHEN 平台返回的审核状态与系统记录的审核状态不一致，THE 广告系统 SHALL 在 15 分钟内更新系统中对应广告对象的审核状态。
3. IF 某广告审核被拒绝，THEN THE 广告系统 SHALL 记录平台返回的拒绝原因。
4. WHEN 某广告审核状态更新为「审核被拒绝」，THE 广告系统 SHALL 通知该广告所属外贸商家客户与负责的平台投手。
5. IF 某平台审核状态拉取失败，THEN THE 广告系统 SHALL 记录失败原因并保留该广告对象上一次成功拉取的审核状态。

### 需求 21：效果看板与业务结果指标

**User Story:** 作为外贸商家客户与平台投手，我希望在统一看板中查看各平台投放效果与对标竞品的关键业务结果数字、浏览并筛选高意向客户商机清单、打开单个客户的完整详情，并可将商机清单导出为 Excel/CSV、导出客户行业调查报告，以便量化获客成效、直接拿到精准客户信息并支撑经营决策。

#### 验收标准

1. THE 效果看板服务 SHALL 基于数据回传服务归一化后的指标，按平台维度聚合并对比展示 Meta、Google、TikTok 各平台的曝光、点击、转化、花费与 ROI 五项指标。
2. WHEN 用户选择时间范围，THE 效果看板服务 SHALL 按所选时间范围筛选展示看板数据，时间范围为最近 1 天至最近 365 天，默认值为最近 7 天。
3. IF 用户所选时间范围的结束日期早于开始日期，THEN THE 效果看板服务 SHALL 返回「时间范围无效」的提示并不更新展示数据。
4. IF 某平台或某维度指标数据缺失，THEN THE 效果看板服务 SHALL 在对应平台或维度标注「数据不可用」并保持其余正常展示，而非中断整个看板展示。
5. THE 效果看板服务 SHALL 计算并展示五项业务结果指标，统一支持按平台（Meta、Google、TikTok）与时间范围（最近 1 至 365 天，默认 7 天）维度计算：
   - **单条有效询盘成本**，计算为「统计区间内花费 / 同区间有效线索数」，其中花费取自数据回传服务归一化后的花费指标；有效线索为背调可信度评估达标（需求 15）或买家意向等级（需求 16）达到用户可配置阈值的商机，阈值缺省时采用系统默认阈值。
   - **客户有效联络率**，计算为「已成功联络的商机数 / 商机总数」，已成功联络指商机跟进状态（需求 17）为「已触达」或「跟进中」且已记录买家回复事件。
   - **各买家意向等级占比分布**，对已分级商机按等级计算 L1/L2/L3/L4 各占比并突出展示「L3+L4 高意向占比」。
   - **投放到首条商机时长**，计算为某广告计划首条商机采集时间与首次投放成功时间（需求 13）之差值，用于支撑「当日投放当日见客资」时效卖点。
   - **客户资产归属与私域沉淀**，展示归属于该商家、持久留存且可导出的商机资产数量与已沉淀至商家私域的商机数量。
6. THE 跟进路由服务 SHALL 为每个商机记录买家回复事件，承载买家回复的来源跟进通道与精确到秒的回复时间，使商机是否收到买家回复可被判定。
7. IF 单条有效询盘成本的有效线索数为零、客户有效联络率的商机总数为零、或各买家意向等级占比分布的已分级商机数为零，THEN THE 效果看板服务 SHALL 将对应指标标记为「不可计算」（与需求 13.3 的零除处理一致）。
8. IF 某广告计划尚无任何商机，THEN THE 效果看板服务 SHALL 将该广告计划的投放到首条商机时长标记为「暂无商机」。
9. THE 广告系统 SHALL 将每条商机数据（含联系方式、背调结果与跟进记录）的数据所有权归属于其所属外贸商家客户（Merchant），在该商家账户名下持久留存且可导出，并保证其不因广告计划停投或重投而丢失。
10. IF 某角色尝试访问非其自身账户名下的商机资产，THEN THE 效果看板服务 SHALL 依据需求 7 的数据隔离拒绝该访问并返回「权限不足」的错误，且不返回该商机资产数据。
11. WHEN 用户发起客户行业调查报告生成请求，THE 效果看板服务 SHALL 基于背调结果（需求 15）、商机数据（需求 14 至需求 16）与产品素材生成含行业分布、客户画像、商机意向等级分布、目标市场与竞争格局概览、获客行动建议维度的报告，支持按平台与时间范围生成并导出。
12. IF 客户行业调查报告某维度所需数据缺失，或底层生成式 AI（Gemini）凭据配置项状态为「未填入」，THEN THE 效果看板服务 SHALL 在受影响维度标注「数据不可用」并继续生成其余维度，而非中断报告生成。
13. THE 效果看板服务 SHALL 提供商机清单视图，以列表形式展示当前商家账户名下全部商机，每行至少包含公司名、姓名、电话、邮箱、来源平台、买家意向等级、背调可信度与跟进状态，并支持按买家意向等级、来源平台、跟进状态与时间范围筛选、按买家意向等级排序（L4 优先）。
14. WHEN 用户发起商机清单导出请求，THE 效果看板服务 SHALL 按当前筛选条件生成包含留资字段（公司名、姓名、电话、邮箱及其余表单字段）、背调补全字段（公司官网、地区、行业、职位、社媒等）、可信度评估、买家意向等级与来源信息的可下载表格文件，导出格式支持 Excel 与 CSV 二者。
15. WHEN 用户打开某条商机的客户详情，THE 效果看板服务 SHALL 展示该商机的完整档案，包含原始留资字段、留资质量校验标注、Gemini 背调补全字段与可信度评估、买家意向等级及其变更轨迹、来源广告与采集时间、跟进状态与跟进剧本。
16. IF 商机清单导出所选范围内无任何商机，THEN THE 效果看板服务 SHALL 返回「无可导出商机」的提示并生成仅含表头的空表格文件，而非报错。
17. IF 某角色发起商机清单视图、导出或客户详情访问且目标商机非其自身账户名下，THEN THE 效果看板服务 SHALL 依据需求 7 的数据隔离拒绝该访问并返回「权限不足」的错误，且不返回任何该商机数据。

## Requirements（第二组 · 高级投放能力全集，本期实现）

> 以下需求 22 至需求 34 为高级投放能力全集，与第一组获客主线**同属本期实现范围**，充分利用三平台官方 API 的高级与独有能力以全面超越竞品。这些能力遵循与主线一致的优雅降级、凭据缺失标记不可用、失败保留数据待重试与单点失败隔离原则。其中仅 LinkedIn（需求 34）为第二期平台扩展位预留。

### 需求 22：平台扩展能力包框架

**User Story:** 作为平台投手，我希望各平台的独有与高级能力以统一的扩展能力包机制按平台命名空间暴露，以便在不破坏统一核心模型的前提下使用平台特定能力，并在平台不支持时获得明确反馈。

#### 验收标准

1. THE 扩展能力调用网关 SHALL 为每个平台扩展能力维护其所属平台标识与所支持平台集合，使每个扩展能力的可用平台范围可被查询。
2. WHEN 用户对某平台发起扩展能力调用且该平台支持该扩展能力且该平台凭据配置项状态为「已填入」，THE 扩展能力调用网关 SHALL 将该调用路由至对应平台适配器执行。
3. IF 用户对某平台发起其不支持的扩展能力调用，THEN THE 扩展能力调用网关 SHALL 返回「该平台不支持此能力」的错误并不执行该调用。
4. IF 用户发起扩展能力调用而目标平台凭据配置项状态为「未填入」，THEN THE 扩展能力调用网关 SHALL 返回「该平台凭据未配置」的错误、将该扩展能力标记为不可用并保持其余平台与统一核心功能正常运行。
5. THE 扩展能力调用网关 SHALL 使新增平台扩展能力的注册不改变统一广告对象模型的字段定义，且不影响未声明该扩展能力的其他平台的功能。
6. WHERE 某平台扩展能力在目标平台暂不可用，THE 扩展能力调用网关 SHALL 将该扩展能力标记为不可用并向用户返回包含能力名称与平台标识的不可用提示，而非中断其余功能。

### 需求 23：Meta Advantage+ 全自动系列

**User Story:** 作为外贸商家客户，我希望创建并管理 Meta Advantage+ 全自动系列，以便借助 Meta AI 自动完成受众与版位投放，同时保留必要的硬控制。

### 需求 33：广告版位（Placement）管理

**User Story:** 作为平台投手，我希望在广告组层级以统一的版位字段配置投放版位，支持由平台自动选择全场景版位或手动选择，以便覆盖各平台原生版位并在目标平台不支持某版位时获得明确提示。

#### 验收标准

1. THE 统一广告模型层 SHALL 在广告组（需求 8）层级提供广告版位字段，作为统一广告对象模型的一个字段，且该字段的配置方式取值为「自动版位」与「手动版位」二者之一，任一时刻有且仅有一个配置方式生效。

5. WHERE 目标平台不支持用户所选的某手动版位，THE 统一广告模型层 SHALL 将该版位标记为该平台不适用并向用户返回包含该版位名称与平台标识的不适用提示（与需求 8、需求 10 的不适用标记机制一致），并保持其余受支持版位正常转换。
6. IF 用户所选手动版位转换为目标平台原生版位参数时校验失败（包括版位取值非法或与广告组其他设置冲突），THEN THE 平台适配器 SHALL 返回包含版位名称与失败原因的校验错误并不保存该版位设置。

### 需求 35：商机数据对外 API（供后续 CRM 接入）

**User Story:** 作为外贸商家客户，我希望系统提供一个标准化的商机数据对外 API，以便后续自有 CRM 系统或第三方系统能安全地拉取与增量同步本商家名下的客户商机资料，无需手工导出导入。

#### 验收标准

1. THE 广告系统 SHALL 提供商机数据对外 API，支持外部系统按所属商家维度查询商机档案，每条返回留资字段（公司名、姓名、电话、邮箱及其余表单字段）、背调补全字段（公司官网、地区、行业、职位、社媒等）、可信度评估、买家意向等级、跟进状态、来源平台与来源广告标识、精确到秒的采集时间与最近更新时间。
2. THE 商机数据对外 API SHALL 要求调用方提供有效的 API 凭证进行鉴权，并仅返回该凭证所绑定商家名下的商机数据。
3. IF API 请求未提供 API 凭证或所提供凭证无效，THEN THE 广告系统 SHALL 拒绝该请求并返回「未认证」的错误，且不返回任何商机数据。
4. IF API 凭证有效但请求的商机不属于该凭证绑定的商家，THEN THE 广告系统 SHALL 依据需求 7 的数据隔离拒绝该访问并返回「权限不足」的错误，且不返回该商机数据。
5. WHEN 调用方提供分页参数发起商机查询，THE 商机数据对外 API SHALL 按分页返回结果并在响应中包含可用于获取下一页的分页游标或标识。
6. WHEN 调用方提供「最近更新时间」起始值发起增量查询，THE 商机数据对外 API SHALL 仅返回该时间之后有新增或变更的商机，用以支撑 CRM 增量同步。
7. THE 广告系统 SHALL 支持为商家签发与吊销 API 凭证，并对 API 凭证按加密存储与日志脱敏的方式管理（与需求 1、需求 6 一致）。
8. IF 某 API 凭证已被吊销而调用方使用其发起请求，THEN THE 广告系统 SHALL 拒绝该请求并返回「未认证」的错误。
9. THE 商机数据对外 API SHALL 对每个 API 凭证施加调用频率限制，并在调用超过限制时返回「请求过于频繁」的错误而非中断服务。
10. THE 商机数据对外 API SHALL 提供稳定的响应数据结构与版本标识，使后续 CRM 接入在该版本契约不变的前提下不受系统内部实现变更影响。
